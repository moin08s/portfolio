// Engineering Philosophy

Why Zero-Dependency & Cryptographic Defensibility?

In an era of bloated dependency trees and software supply chain vulnerabilities, I advocate for defensible engineering: software with predictable memory footprints, zero unvetted runtime dependencies, and cryptographic algorithms strictly adhering to established standards (RFC 4226, RFC 6238, RFC 2898).

Never Roll Your Own Cipher: Strict composition of battle-tested primitives (crypto/aes, crypto/cipher, crypto/hmac).
Zero-Allocation Inner Loops: Memory slice recycling and constant-time verification preventing timing side-channel attacks.
Atomic State & Durability: Strict lockfile concurrency, temporary staging, and synchronous directory syncing.
